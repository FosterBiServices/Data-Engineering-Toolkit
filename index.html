Foster BI Data Engineering Toolkit

Tools for building Azure Data Factory pipelines, the Databricks notebooks they run, and pandas scripts for files. Each page writes the exact parts itself; Copilot is optional and only for logic described in plain words.

Check everything before you use it. Generated pipelines, SQL and notebooks can be wrong, and AI can make mistakes. The toolkit is provided as is, without warranty, and you use it at your own risk. Read the full disclaimer.

How the tools fit together

  • ADF Pipeline Generator moves the data: from a database table or landed files into a database table or the raw zone, with a watermark, a run log and a failure path. It can then run your notebooks, passing each one batch_id and the path it landed.
  • Python Notebook Generator writes those notebooks: bronze lands the files, silver cleans and merges them, gold aggregates for reporting. Each returns its row counts to ADF.
  • Python Script Generator is for work outside the pipeline: a pandas script or Jupyter notebook that cleans and checks one file on your own computer.
  • All three are safe to rerun, and keep bad data visible (a quarantine folder or table, or a rejected-rows file) and never drop it silently.

Good to know

  • Nothing leaves your browser. The pages don’t send data anywhere. A prompt only reaches Copilot when you paste it yourself, and it carries column names and types, never rows of data.
  • What the pages keep: your entries and team standards, in this browser’s storage for this site. They aren’t on another computer or in another browser.
  • Never paste secrets. Connection strings, keys and passwords belong in Azure Key Vault, reached through the linked service. The pipeline checker flags anything that looks like one.
  • Clear entries on each tool empties that tool. empties them all.

Disclaimer: use at your own risk

  • Check all of the work. Everything the toolkit produces, with or without AI (pipeline JSON, SQL scripts, notebooks, build steps and check findings), is a starting point to review, not a finished answer. The pages check structure and names; they can’t see your data, your factory or your workspace.
  • AI can make mistakes. Copilot replies can be wrong, incomplete or out of date, and can refer to columns that don’t exist. The pages check what they can, but they can’t catch every error in logic or meaning. Read every reply before you use it.
  • Test in dev first. Scripts create and change tables and stored procedures, and pipelines move and delete files. Run them against a development environment and a small window before production.
